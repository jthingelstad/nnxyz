# nnxyz gallery project

This project is the local Astro gallery baseline for the collector's owned nnxyz artworks. Scrimshaw is the only related artist included for now.

The site is named **The nnxyz Rooms** (collector's choice, October 15, 2026); the name is the wordmark, the default title, the front-page heading, the share site name and the first line of `llms.txt`. The collector selected `nnxyz.thingelstad.xyz` as the gallery's public domain. Use `https://nnxyz.thingelstad.xyz` as the production site URL when implementing canonical URLs, sharing metadata and deployment configuration. S3/CloudFront infrastructure and GitHub OIDC deployment are implemented; current resource IDs are in `infra/deployment.json`, and DNS/operating instructions are in `docs/deployment.md`.

## Website priorities

- Prioritize beautiful native SVG artwork reconstructed from archived brush strokes over the small published PNGs where fidelity and performance permit. Validate geometry, stroke order, brush widths, alpha blending, background/reference passes and rendering cost across representative sparse and dense works before promoting the full collection. Keep derived SVGs outside immutable `collection/`.
- Make watching the drawing occur a central interaction, with play/pause, scrubbing and speed controls. The archive records stroke and point order without precise point timing; label playback speed as reconstructed rather than original drawing time.
- The collector explicitly wants continuous drawing within each stroke, rather than whole strokes/layers appearing at once. Progressively reveal the recorded brush path, preserving order, width, color and alpha; validate the finished replay against the native SVG still. Playback timing is reconstructed.
- The collector is interested in PixiJS flourishes. Evaluate subtle effects around the presentation and interaction with reduced-motion support. Preserve an accurate native SVG still view; loading an SVG as a PixiJS texture rasterizes it, so it does not establish resolution-independent artwork rendering.
- Use Tinylytics for web analytics and per-artwork kudos. Give each artwork a stable canonical page path derived from its drawing CID; kudos on cards and detail pages must refer to that same artwork path, keeping repeated titles distinct.
- The collector supplied Tinylytics embed ID `7MaUUztU7BVzhcxntCUh`. Integration guidance and the exact snippet are saved in `design/tinylytics.md`. Load one shared production script; keep development and review previews from sending production hits or kudos.
- Existing experience with Eleventy is useful but should not dominate framework selection. Evaluate the interactive artwork viewer and asset pipeline first; The collector approved implementing the revised design baseline on October 13, 2026. Astro with TypeScript is implemented; hosting is S3/CloudFront with GitHub Actions.

- `../nifty-ink-archive` is the permanent archive. Treat it as read-only. Keep website files independent: copy assets, never move them out of the archive or create links into it.
- `collection/` contains exact copies of selected archived artwork files and relevant provenance. Keep the imported source bytes immutable. Put transformations, thumbnails, SVG exports, and website code elsewhere.
- `data/gallery.json` is the gallery catalog; paths are relative to the project root. `data/collections.json` defines the series and related groupings. Imported archival JSON paths are relative to `collection/`.
- Creator addresses, drawing CIDs, wallet addresses, chain IDs and token IDs are stable identifiers. Do not merge editions or creator identities based only on display names.
- Nifty Faces, NNOTB and Rawblocks are the three primary nnxyz series inferred from artwork titles. Other nnxyz works are retained separately rather than dropped. Scrimshaw and the related dataset are separate groups whose display can be decided during site design.
- Use `python3 tools/verify-collection.py` after dataset changes; add `--compare-archive` when the original archive is available.
- `previews/` contains existing stroke/SVG references; `source/archive/` preserves original preview/exporter references. Original vendor distributions remain in the permanent archive. The gallery is implemented in `src/`; `dist/` is disposable build output. Published media is permanent and write-once (see below).

## Curatorial charter

- Visitors can choose a white or black gallery background using the shared header switch. Default to white, persist the explicit choice across pages/visits, and initialize it before first paint. Never invert artwork colors or change archived SVG/download bytes; preserve the original white drawing canvas underneath translucent/unpainted areas. Theme the navigation, curator text, controls, notices, dialog and fullscreen surround consistently.
- Aim for a museum experience: a clean, modern white background, artwork given visual priority, a collector introduction, and browsing that supports sustained looking.
- Design feedback on October 13, 2026: the initial serif typography felt out of step with the art and the layout was too structured. Use quieter neutral sans-serif typography, fewer dividers and panels, and more space for the art. The collector approved building the revised concepts in `design/concepts/2026-10-13-v2/` as a baseline; keep the introduction and curatorial information available without competing with the artwork.
- October 14 direction supersedes the grid-first entrance: a white landing page with three short collector welcome paragraphs on the left in dark gray serif type, and one continuously replaying artwork on the right. Keep navigation and controls in quiet sans-serif. Four entrances: Faces, On the Block, Rawblocks, and Other & related. No All Works link or global artwork grid; visitors enter through collections. Develop bounded, image-grounded exhibitions around 20 works, never more than 30, with chapters, explained comparisons, contrasts and a closing. The experience should help visitors and the collector learn through looking. `design/exhibition-experience.md` and `curation/exhibitions/` record the design and content proposal. The exhibition entrance and chapter system are implemented in Astro; publication uses the verified main-branch deployment pipeline. The collector deferred the new welcome text until the end.
- The story layer (October 16, 2026, `design/depth-plan.md` section "The story layer"): background articles on Nifty Ink, the collector, the artist's project and the year 2022, drafted under `curation/research/story/`, plus per-work facts (the artist's own post about a work, the day the collector bought it) woven into rooms and artwork pages. The site tells the whole story: platform, artist, collector, market, and the art.
- October 15 direction supersedes "identify the curator as AI": the curation is unsigned, like museum wall text. No room, wing or artwork page names the curator or labels text "AI curator". The one exception, asked for by the collector later that day, is `/notes/` (Notes from the curator), which says how the rooms, text, audio tour and map were made and that an AI assistant made them with the collector; it names no model. October 16, 2026 supersedes the earlier limits on the collector: the collector, Jamie Thingelstad, is part of the story and may be named, quoted (from thingelstad.com, The Weekly Thing and the ledger) and described in room, artwork and story text wherever it helps. The collector's instruction: "You have no limitation in talking about the collector or any of those things. Just go and tell the story and show the art and help people connect and feel it." Later on October 16 the collector set one limit: only the collector is named. No other member of the collector's family is named or described anywhere on the site or in the curation text; other household wallets appear in research data by address only. Market events (Terra, May 2022; FTX, November 2022) are named where they bear on a room; comparisons to other artists are the gallery's and are made plainly. The collector is drawn to patterns and emotional range, from joy to anger, and sees a related visual character in scrimshaw. Gallery text is written as segments tied to works, and every work gets a standalone caption, so both can be built without rewriting. The screen saver is implemented at `/screensaver/` (`src/scripts/screensaver.ts`, works and captions from `screensaver/data.json`; `#room=` or `#wing=` in the hash limits it): it draws each Nifty Ink work from its strokes at a slower reconstructed pace, holds it, then moves on, sharing `src/scripts/replay.ts` with the artwork viewer; Abstract works hold as stills. - Use an accessible, specific, restrained museum-label voice. Avoid generic praise and repeated stock metaphors. October 16, 2026: the collector removed the earlier rule against saying what the artist meant or felt; it was meant for the first labelling pass only. ## Local implementation and verification

- Media (SVGs, PNGs, WebPs, Abstract originals, record downloads) was generated once and lives permanently in the web bucket under `art/`, `png/`, `raster/`, `records/` and `abstract/{images,originals,records}/`. The site only references those URLs; builds and deploys never read, copy or upload media, and the deployment role cannot write them. `data/media.json` records every key's SHA-256; `tools/validate-site.py` fails on any media URL missing from it. Never overwrite a published key: a new rendering gets new key names. `npm run media:generate` renders into ignored `media/`, `npm run media:publish` uploads only missing keys (write-once) and rewrites the manifest, `npm run media:verify` is read-only. See `docs/deployment.md`.
- `npm run dev` and the browser tests proxy media paths to CloudFront, so site work needs no hydration. Hydrate only to validate sources/curation (`.github/workflows/archive.yml`) or to generate media. `data/tokens.json` holds the owned token identities extracted from the archive by `tools/build-token-links.py`.
- `npm run dev` serves the local review gallery on loopback. `npm run build` creates 698 HTML pages in `dist/` (33 are redirects from retired addresses; 747 once the After Nifty Ink media is published), plus the screen saver's `screensaver/data.json`, `llms.txt` and `llms-full.txt` (built from the room files by `src/lib/llms.ts`), `robots.txt` and the sitemap; `tools/validate-site.py` requires the sitemap to list exactly the public pages. No hosting or DNS mutation is implied by a local build.
- Artwork detail, enlargement and replay use native SVG for every work. Browsing uses lossy WebPs at 320/640/1200/1600/2000 px (`srcset`), rendered from each native SVG in Chromium by `tools/build-raster-assets.mjs`, which also checks each render against the archived PNG at archive resolution. Size them for retina: the largest width must cover every slot at 3x on phones and 2x on desktops (the archived PNGs, about 790 px, are too small for 2x displays). The same WebPs are the artwork page's poster while its SVG downloads. Abstract WebPs are lossy too; only original JPEG/PNG downloads are byte-exact. Do not simplify original geometry without explicit fidelity verification.
- Run `npm run check`, `npm test`, `npm run build`, and `npm run test:browser` against a running local server after meaningful viewer/layout changes. The browser suite writes evidence to `/tmp/nnxyz-gallery-qa`; Chromium must be installed with Playwright or specified via `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
- Browser fidelity checks cover archived PNGs plus the original quadratic brush geometry with historical round dots. Current Chromium Canvas suppresses zero-length strokes, so account for that difference rather than deleting dots from SVG. Compare at archived raster resolution; tiny thumbnails introduce different antialiasing.
- Deployment must serve SVGs with compression: full-precision assets total about 1.5 GiB and the largest is about 19 MiB uncompressed. Deployment precompresses text assets, including the largest SVGs.
- Set `PUBLIC_TINYLYTICS_ENABLED=true` only for the production build. The browser additionally checks the production hostname before requesting Tinylytics. Never send live hits/kudos during QA.
- Design and QA evidence: `design/implementation.md`, `design/qa-baseline.md`; baseline acceptance: `design/concepts/2026-10-13-v2/acceptance.json`.

## Git and delivery

- Public repository: `jthingelstad/nnxyz`. Imported `collection/` is intentionally ignored; hydrate the hash-pinned private S3 snapshot rather than committing artwork. Keep original archive and source bytes immutable.
- CI performs formatting/lint, type/unit checks, CodeQL, page/link and published-media checks and browser tests without AWS credentials. Main alone publishes the exact verified build. The separate archive workflow validates sources, curation and token links when they change.
- AWS IAM roles belong to `nnxyz-delivery`; build is read-only, publication is bounded to this site bucket/CDN. Never substitute broad local credentials in the publication script or add static GitHub AWS keys. Local infrastructure work uses AWS MCP and reviewed CloudFormation change sets.
- Routine deployments do not modify infrastructure, regenerate curation, bulk-delete artwork or alter the permanent archive. Deploys upload pages only, invalidate only page paths, and verify the deployed revision.
